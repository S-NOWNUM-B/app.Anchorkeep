# Anchorkeep — threat model

Одна страница: от чего MVP защищает, от чего нет и на каких допущениях это держится. Основа — [PRD](PRD.md), [ARCHITECTURE](ARCHITECTURE.md) и ADR 0003, 0005–0007.

## Что защищаем

| Актив | Где живёт |
|---|---|
| Записи сейфа (пароли, заметки) | только в payload `.akv` / `.akbackup` под AES-256-GCM |
| Мастер-пароль | только в голове пользователя; в приложении — на время вывода KEK |
| Ключ сейфа (VK), KEK | только в памяти, пока сейф открыт |
| Devnet-ключ сейфа | внутри зашифрованного payload (ARCHITECTURE, «Формат файла») |
| Актуальность бэкапа | SHA-256 файла и его `revision` в `VaultRecord` в Solana devnet |

## Модель нарушителя

1. **Получил файл** — бэкап с флешки, из облака, из чужих рук; пароля не знает.
2. **Может подменить файл** — положить пользователю старый валидный бэкап или изменённый файл.
3. **Видит цепочку** — читает всё, что публично в Solana devnet.
4. **Кратко держит разблокированное устройство** — без root и вредоносного ПО.

## От чего защищаем

| Угроза | Защита | Где |
|---|---|---|
| Чтение украденного файла без пароля | Argon2id (64 MiB, 3 итерации) → KEK → VK → AES-256-GCM; перебор стоит дорого | `core/crypto` |
| Порча или подмена байтов файла, заголовка, обёртки ключа | Тег GCM; весь заголовок — AAD payload, `vaultId` — AAD обёртки (ADR 0005) | `core/vault` |
| **Откат на старый валидный бэкап** | `revision` под тегом GCM, в цепочке — `revision` и хеш заверенного файла → **Outdated** (ADR 0006) | `core/solana`, F9 |
| Неизвестный или изменённый файл выдают за заверенный | Хеш не совпал → **Unknown**, а не Verified | F9 |
| Заверение чужим ключом или старой версии поверх новой | `has_one = owner` → `Unauthorized`; версия только растёт → `VersionMismatch` | `vault_registry` |
| Порча файла при сбое записи | `tmp` → fsync → `rename` | `atomic_write.dart` |
| Смена пароля с чужого открытого устройства | Нужен текущий пароль; новый VK — старый пароль не читает новые файлы (ADR 0007) | `change_password.dart` |
| Подсматривание на открытом устройстве | Автоблокировка (5 мин, при сворачивании), очистка буфера через 30 с, `FLAG_SECURE` на Android | `core/security` |
| Утечка через цепочку | В Solana только pubkey, `vault_id`, версия, SHA-256 зашифрованного файла | правило безопасности 7 |
| Нет сети — ложный Verified | Ошибка RPC → **Offline**, а не Verified | `backup_verification.dart` |

## От чего НЕ защищаем

| Угроза | Почему | Как смягчаем |
|---|---|---|
| Потеря мастер-пароля | Восстановления нет by design | Предупреждение в онбординге (F1) |
| Скомпрометированное устройство: root, кейлоггер, вредонос, дамп памяти | Вне модели; Dart не гарантирует обнуление памяти | Короткое время жизни ключей, блокировка сбрасывает сессию |
| Слабый мастер-пароль | Argon2id замедляет, но не спасает | Индикатор сложности (F1) |
| **Откат между заверениями** | Свежесть ровно такая, как часто заверяют: правки без заверения → подмена на последнюю заверенную версию даст **Verified** | Экран заверения будет предлагать заверить, когда `lastAnchoredRevision` отстаёт от `revision` (MAIN-43) |
| Старые бэкапы после смены пароля | Открываются старым паролем (ADR 0007) | Считать раскрытыми, если старый пароль утёк |
| Метаданные активности on-chain | Видно, **когда** и **сколько раз** сохраняли между заверениями (`version` = `revision`), и что один `owner` заверяет один `vault_id` | Осознанный trade-off PRD |
| Подложный ответ RPC | Приложение доверяет `api.devnet.solana.com`, своего лёгкого клиента нет; от MITM — только TLS | Фиксированный RPC в `SolanaConfig` |
| Права на обновление программы | Upgrade authority — один ключ разработчика (`FZ3G…`): он может заменить логику `vault_registry` | MVP в devnet; для mainnet — мультисиг или отказ от upgrade |
| Сброс или недоступность devnet | Записи пропадут → **Not anchored** / **Offline**, данные сейфа целы | Статус честно говорит «не проверено» |
| Снимки экрана на Windows, история буфера (Win+V) | `FLAG_SECURE` есть только на Android; системную историю буфера не контролируем | Автоочистка через 30 с |

## Допущения

- Пользователь сам решает, когда заверять; приложение подсказывает, но не заверяет без него.
- Devnet-SOL на заверение пользователь получает сам (faucet); без SOL F8 недоступна, F9 работает.
- Целевые платформы — Android и Windows (PRD); остальные собираются, но не оцениваются.
