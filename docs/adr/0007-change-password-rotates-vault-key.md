# 0007. Смена мастер-пароля заменяет ключ сейфа

- **Статус:** Accepted
- **Дата:** 2026-10-21
- **Задача:** MAIN-50 / AK-53

## Контекст

ARCHITECTURE.md и задача предписывали: «смена пароля = перешифровать только VK, payload не трогаем». Это не работает по двум причинам.

1. По ADR 0005 в AAD payload входит весь заголовок, включая `kdf.salt` и `wrappedKey`. Новая соль и новая обёртка меняют AAD, поэтому payload всё равно нельзя оставить как есть: его нужно перешифровать. Стоимость нулевая, payload и так перешифровывается при каждом сохранении.
2. Если оставить прежний ключ сейфа (VK) и только перевернуть обёртку, смена пароля не защищает от главной угрозы. Человек, который знает **старый** пароль и имеет **любую** старую копию файла, получит из неё прежний VK и сможет читать все новые файлы. А пароль меняют именно тогда, когда подозревают, что он скомпрометирован.

## Решение

`changeMasterPassword(session, current, next, write)`:

1. Проверяет **текущий** пароль (расшифровкой обёртки ключа), даже если сейф уже открыт: с разблокированного телефона нельзя сменить пароль, не зная старого. Неверный → `VaultAuthException`.
2. Генерирует **новый VK**, новую соль, новый KEK из `next`; параметры стоимости Argon2id берутся прежние (подобраны бенчмарком).
3. Перешифровывает payload новым VK с новым AAD, `revision + 1`.
4. Отдаёт байты в `write`. Сессия (ключ, заголовок) обновляется **только после успешной записи**; при сбое остаётся прежней и работает со старым паролем. Старый VK и промежуточные KEK уничтожаются.
5. Пустой новый пароль → `ArgumentError`.

## Альтернативы

| Вариант | Почему отвергнут |
|---|---|
| Только заново обернуть прежний VK (как в задаче) | Не решает п. 2 контекста; к тому же payload всё равно перешифровывается из-за AAD |
| Не требовать текущий пароль при открытом сейфе | Любой, кто взял разблокированный телефон, сменил бы пароль и забрал сейф |

## Последствия

- Старые бэкапы остаются открываемы **старым** паролем: смена пароля защищает новые файлы, а не уже утёкшие копии. Если старый пароль скомпрометирован, старые бэкапы нужно считать раскрытыми.
- Файл меняется (`revision + 1`), поэтому после смены пароля его нужно заново заверить в Solana (`commit_version`).
- Смена пароля стоит одной операции Argon2id для проверки текущего и одной для нового.
