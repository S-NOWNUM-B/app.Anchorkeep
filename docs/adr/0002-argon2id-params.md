# 0002. Параметры Argon2id

- **Статус:** Proposed (Windows измерен; для Android нет устройства, решение по оценке, ждёт подтверждения команды)
- **Дата:** 2026-11-21
- **Задача:** MAIN-19 / AK-03

## Контекст

PRD требует: разблокировка ≤ 1.5 с на средне-бюджетном Android. Argon2id в приложении считает пакет `cryptography` на чистом Dart (`cryptography_flutter` ускоряет AES-GCM, но не Argon2id), поэтому на слабом телефоне он может быть медленным. Стартовые параметры из ARCHITECTURE.md: 64 MiB, 3 итерации, 1 поток.

Параметры хранятся в **заголовке файла**. Следствие: файл, созданный на быстром ПК, открывается на телефоне **с теми же параметрами**, и время разблокировки определяет самое медленное устройство, на которое файл попадёт (бэкап с ПК на телефон). Менять значения по умолчанию можно без миграции: старые файлы читаются со своими параметрами.

## Замеры

Утилита: `app/tool/argon2_bench.dart` (консоль) и `app/tool/argon2_bench_main.dart` (мини-приложение, только `--release`). Время — медиана 3 прогонов после прогрева. Реальные раннеры GitHub Actions замерены workflow `bench-argon2.yml` (два прогона подряд, результаты совпали в пределах 5%).

| Память | Итераций | Mac M1 Pro | Windows (EPYC 7763, CI) | ARM64 (Neoverse-N2, CI) | Linux x64 (EPYC 9V45, CI) |
|---|---|---|---|---|---|
| 19 MiB (минимум OWASP) | 2 | 97 мс | 117 мс | 133 мс | 65 мс |
| 32 MiB | 2 | 169 мс | 207–230 мс | 233 мс | 115 мс |
| 32 MiB | 3 | 247 мс | 313–319 мс | 343–347 мс | 171 мс |
| 64 MiB | 3 | 514 мс | 636–644 мс | 706–710 мс | 359 мс |

Самая длинная пауза основного потока (если больше ~50 мс, экран подвисает): Mac 6–14 мс, Windows 16–28 мс, ARM64 5–7 мс, Linux x64 4–7 мс. Время растёт почти линейно от «память × итерации».

**Android-эмулятор (Pixel API 36, arm64, release) для решения не используется:** на одном и том же APK 64 MiB / 3 итерации дали то 0.7 с, то 3.3–3.7 с. Эмулятор работает на процессоре Mac, и его скорость плавает в разы от нагрузки хоста.

**Чего нет:** реального телефона. В команде нет Android-устройства под рукой, поэтому ARM64-сервер (Neoverse-N2, ядро одного поколения с флагманскими Cortex-X2/A710) служит **верхней границей скорости телефона**. Телефон среднего класса (Cortex-A76/A78 на низких частотах и A55) медленнее в несколько раз. Это оценка, не замер.

## Решение

1. **Isolate не нужен.** Пакет сам регулярно отдаёт управление циклу событий: самая длинная пауза 5–14 мс при кадре в 16 мс, время в isolate и без него совпало (±3%). Isolate копировал бы пароль в чужую память без выигрыша. Тест `deriveKek не блокирует основной поток` страхует от регрессии. Если на телефоне пауза окажется > 50 мс, пересмотреть.
2. **Правило выбора параметров.** Берём самый сильный набор из ряда `64/3 > 32/3 > 32/2 > 19/2` (память MiB / итерации), у которого на самом медленном целевом устройстве время ≤ 1.5 с и пауза UI ≤ 50 мс. Ниже `19 MiB / 2` не опускаемся: это минимум OWASP для Argon2id.
3. **Предлагаемое значение по умолчанию: 32 MiB / 3 итерации** (сейчас в коде 64 MiB / 3).
   - **Windows:** 64/3 = 0.64 с, укладывается с большим запасом. Платформа ограничением не является.
   - **Android:** на лучшем доступном аналоге 64/3 = 0.71 с; если телефон среднего класса в 3–4 раза медленнее, получаем 2.1–2.8 с, что хуже цели PRD (≤ 1.5 с). 32/3 даёт 0.35 с и ту же оценку 1.0–1.4 с. То есть 64/3 с высокой вероятностью не укладывается на целевом телефоне, а 32/3 вероятнее всего да.
   - Безопасность: 32 MiB / 3 выше рекомендуемого минимума OWASP (19 MiB / 2); цена перебора на пароль вдвое ниже, чем при 64/3.
   - Параметры в заголовке файла: если появится телефон и окажется запас, значение можно поднять, ничего не мигрируя.
   - Код и документы (`KdfParams.defaults()`, ARCHITECTURE.md, THREAT_MODEL.md) меняются после подтверждения команды.

## Как замерить

- **Android** (когда появится устройство): установить APK утилиты (`flutter build apk --release --target-platform android-arm64 -t tool/argon2_bench_main.dart`) или `flutter run --release -t tool/argon2_bench_main.dart -d <устройство>`, открыть приложение и дождаться таблицы. Запустить 2–3 раза.
- **Windows и ARM64 Linux:** уже в CI (`bench-argon2.yml`, запуск вручную или при изменении утилиты). Локально: `cd app && flutter pub get && dart compile exe tool/argon2_bench.dart -o argon2_bench.exe && .\argon2_bench.exe`.
- Результат (модель устройства, таблица) добавить в раздел «Замеры» этого ADR.

## Альтернативы

| Вариант | Почему отвергнут |
|---|---|
| Вынести расчёт в isolate | Не даёт выигрыша (измерено), копирует пароль в чужую память |
| Нативный Argon2 через FFI | Новая зависимость и нативная сборка под Android и Windows; держим как запасной вариант, если чистый Dart окажется слишком медленным даже на 19 MiB |
| 1 итерация вместо 2–3 | Ниже рекомендации OWASP (при 19 MiB минимум 2 итерации) |

## Последствия

- Смена значений по умолчанию не ломает существующие сейфы: они остаются на своих параметрах. `changeMasterPassword` (ADR 0007) переносит параметры стоимости из старого заголовка, так что новые значения получают только новые сейфы.
- После финального решения обновить числа в ARCHITECTURE.md («Криптосхема») и THREAT_MODEL.md («Чтение украденного файла без пароля»).
