# 0005. AAD и проверка целостности файла `.akv`

- **Статус:** Proposed
- **Дата:** 2026-10-21
- **Задача:** MAIN-24 / AK-10, MAIN-25 / AK-11

## Контекст

ARCHITECTURE.md задаёт AAD payload как «канонический JSON заголовка (без поля `payload`)», но не определяет, что такое «канонический». Если две реализации соберут JSON по-разному (порядок ключей, пробелы, формат чисел), тег AES-GCM не сойдётся и сейф не откроется. Если брать AAD из исходных байт файла, а поля читать после парсинга, — в файле можно оставить дубликаты ключей или лишние поля, которые парсер прочитает иначе, чем проверил тег.

Отдельно: обёрнутый ключ сейфа (VK) шифруется ключом KEK, и для него AAD в ARCHITECTURE.md не указан.

## Решение

1. **AAD payload** собирается заново из уже распарсенных полей заголовка, в фиксированном порядке:
   `magic, formatVersion, vaultId, revision, kdf{alg, memoryKiB, iterations, parallelism, salt}, wrappedKey{nonce, ciphertext}` → `jsonEncode` без пробелов → UTF-8.
   Бинарные поля — стандартный base64 с паддингом. Неизвестные поля в заголовке → `FormatException` до расшифровки.
2. **AAD обёртки VK** = 16 байт `vaultId`. Ключ сейфа привязан к своему сейфу: обёртку из одного файла нельзя вставить в другой.
3. Любая ошибка расшифровки (неверный пароль, подмена ciphertext, заголовка, `revision`) → одно исключение `VaultAuthException` без деталей.

Следствие п. 1: `revision` и параметры KDF защищены тегом payload. Подмена номера ревизии в файле ломает расшифровку.

4. **Пароль** передаётся в Argon2id как есть (UTF-8), без Unicode-нормализации. Нормализация NFC потребовала бы зависимости, которой нет в stdlib Dart.

## Альтернативы

| Вариант | Почему отвергнут |
|---|---|
| AAD = исходные байты заголовка из файла | Парсер и проверка тега видят разные данные (дубликаты ключей, лишние поля) |
| RFC 8785 (JCS) для канонизации | Нужна зависимость или своя реализация; фиксированного порядка полей достаточно, потому что схема заголовка известна |
| Без AAD у обёртки VK | Обёртку можно переносить между сейфами; защита стоит 16 байт |

## Последствия

- Добавление поля в заголовок = новый `formatVersion` и правка порядка полей в коде.
- Чтобы проверить файл, достаточно пароля: отдельного MAC или подписи не нужно.
- AAD защищает от подмены, но не от отката на старый целый файл — для этого anchoring в Solana (F8/F9).
- Риск п. 4: «й» одним символом и «и» + знак краткости дают разные ключи. Менять правило позже нельзя без миграции сейфов.
