# Регресс зоны Core (MAIN-57)

Прогон по чек-листу зоны Core: шифрование и формат сейфа, бэкап, безопасность. Дата: 2026-11-21, ветка `dev`.

**Стенд:** Android-эмулятор (Pixel, API 36, arm64), release-сборка из `dev`; для ручных сценариев с видимым экраном использована копия сборки без `FLAG_SECURE` (с флагом скриншоты чёрные). Файл сейфа читался и подменялся через `adb root`. **Windows не проверялся** (нет устройства); реального телефона тоже нет: эмулятор не годится для оценки скорости (ADR 0002).

## Автотесты

216 тестов, 0 упало, 3 пропущено (интеграционные тесты `core/solana` против devnet, включаются вручную). Объявлений `test` по областям Core: `crypto` 11, `vault` 64, `security` 35, `android` 1 (часть объявлений в цикле порождает несколько случаев, поэтому общая сумма больше).

## Найденное

| Задача | Суть | Статус |
|---|---|---|
| MAIN-68 | Системное окно сохранения или выбора файла сворачивало приложение, и автоблокировка выбрасывала из сейфа прямо после экспорта | исправлено (`AutoLockPause`), проверено на эмуляторе: после экспорта сейф остаётся открытым, обычное сворачивание блокирует по-прежнему |

| MAIN-70 | В интерфейсе и в имени бэкапа «CipherVault» вместо Anchorkeep | нужно решение команды |

## Наблюдения (не воспроизведены, причина не установлена)

1. **Падение процесса `SIGSEGV` в потоке `DartWorker`** при проверке пароля, когда на Mac почти не было свободной памяти (два эмулятора и демоны Gradle). После освобождения памяти не повторилось ни разу (4 неверные попытки подряд, память стабильна).
2. **Однократное общее сообщение «Не удалось открыть сейф»** (ветка не-`VaultAuthException`) при верном новом пароле сразу после смены пароля; файл при этом был корректен (ядро открывало его тем же паролем), в трёх повторах, включая ту же последовательность, не воспроизвелось. Если повторится, нужно логировать тип исключения в этой ветке.
